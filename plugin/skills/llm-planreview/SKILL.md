## LLM Router - 플랜/설계 검토

GPT `strategist` 전문가가 현재 플랜이나 설계를 아키텍처, 설계 패턴, 리스크 관점에서 검토합니다.

### 실행 흐름

1. **플랜 파일 탐색**: 현재 활성 플랜 파일을 찾습니다
   - `.claude/plans/` 디렉토리에서 가장 최근 플랜 파일 확인
   - 또는 사용자가 지정한 파일/내용 사용

2. **플랜 내용 읽기**: Read 도구로 플랜 파일 내용을 가져옵니다

3. **GPT 설계 전문가에게 검토 요청**:

```
consult_expert({
  expert: "strategist",
  question: "다음 설계/플랜을 검토해주세요. 파일 분할 적절성, 서브태스크 간 의존성, 인터페이스/데이터 흐름 모순, 빠진 예외 처리, 통합 리스크를 중심으로 평가해주세요.",
  context: "<플랜 파일 전체 내용>"
})
```

4. **검토 결과 보고**: 전문가의 피드백을 정리하여 사용자에게 보고

### 검토 관점

- 파일 분할이 적절한지
- 서브태스크 간 의존성이 없는지
- 인터페이스/데이터 흐름이 모순 없는지
- 빠진 예외 처리, 테스트 포인트가 없는지
- 통합 리스크가 있는지

### 핵심 원칙

- **플랜 파일을 반드시 먼저 읽어서** context로 전달
- 검토 결과에 문제가 있으면 사용자에게 수정 제안 보고

### 백그라운드 결과 확인 주기

백그라운드로 실행한 경우, 다음 간격으로 `background_expert_result`를 호출하여 결과를 확인하세요:

| 회차 | 대기 시간 | 누적 |
|------|----------|------|
| 1차 | 3분 | 3분 |
| 2차 | 2분 | 5분 |
| 3차 | 1분 | 6분 |
| 4차 | 1분 | 7분 |
| 5차 | 1분 | 8분 |

완료되지 않았으면 이후 1분 간격으로 계속 확인합니다.
