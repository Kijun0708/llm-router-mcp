## LLM Router - 페르소나 전문가 검토

blank 전문가에게 원하는 페르소나를 부여하여 특정 관점에서 검토/분석합니다.

### 사용 가능한 blank 전문가

| Expert ID | 모델 | 특징 |
|-----------|------|------|
| `gpt_blank_1` | GPT 5.5 | GPT 범용 - 설계/분석에 강함 |
| `gpt_blank_2` | GPT 5.5 | GPT 코드특화 - 구현 관점에 강함 |
| `gemini_blank_1` | Gemini 3.1 Pro | Gemini 고성능 - 다각도 분석에 강함 |
| `gemini_blank_2` | Gemini 3 Flash | Gemini 빠른응답 - 간단한 검토에 적합 |

### 기본 사용법

사용자가 페르소나를 지정하면 해당 역할의 전문가로 응답합니다:

```
consult_expert({
  expert: "gpt_blank_1",
  persona: "<사용자가 지정한 페르소나>",
  question: "<사용자의 질문 또는 검토 요청>",
  context: "<관련 코드, 설계, 플랜 내용>"
})
```

### 전문가 선택 기준

| 상황 | 추천 전문가 | 이유 |
|------|-----------|------|
| 설계/아키텍처 관점 검토 | `gpt_blank_1` | GPT의 구조적 사고 |
| 코드 구현 관점 검토 | `gpt_blank_2` | 코드 특화 |
| 다각도 비판적 분석 | `gemini_blank_1` | Gemini의 분석력 |
| 빠른 간단 검토 | `gemini_blank_2` | 빠른 응답 |
| 비개발 자문 (투자, 법률 등) | `gpt_blank_1` | 범용성 |

### 다중 페르소나 병렬 검토

2개 이상의 관점으로 동시에 검토하려면 반드시 병렬로 실행합니다:

```
consult_experts_parallel({
  experts: [
    {
      expert: "gpt_blank_1",
      persona: "시니어 백엔드 개발자",
      question: "구현 가능성 관점에서 검토해주세요.",
      context: "<검토 대상 내용>"
    },
    {
      expert: "gemini_blank_1",
      persona: "보안 아키텍트",
      question: "보안 관점에서 검토해주세요.",
      context: "<검토 대상 내용>"
    }
  ]
})
```

### 페르소나 예시

- `시니어 백엔드 개발자` - 구현 가능성, 성능, 확장성
- `DBA` - DB 설계, 쿼리 최적화, 인덱싱
- `QA 엔지니어` - 테스트 케이스, 엣지 케이스
- `투자 전문가` - 시장 분석, 투자 전략
- `프로덕트 매니저` - 사용자 가치, 우선순위
- `기술 문서 작성자` - 문서 구조, 가독성

### 핵심 원칙

- **`persona` 파라미터 필수** — blank 전문가는 페르소나 없이 사용 불가
- **검토 대상을 반드시 context로 전달** — 플랜 파일, 코드, 설계 문서 등을 먼저 읽어서 전달
- **2명 이상 검토 시 반드시 `consult_experts_parallel` 사용**
